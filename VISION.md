# Benchpress: product vision

## What we built

A task-agnostic control loop that makes a frontier model finish multi-app work safely: policy
sweep, locked look-alikes, a code-enforced mutation gate, read-back verification and reviewed
deliverables. It runs on real Slack, Stripe, HubSpot and Gmail, and on local twins of ArgaBench's
published seed graded by ArgaBench's unmodified grader.

It ships as an open-core package on PyPI, [`benchpress-agent`](https://pypi.org/project/benchpress-agent/)
(0.1.0 to 0.7.0, all built on 2026-09-13):

- `wrap(model, executor)` over any `execute_tool`-shaped tool layer, and `benchpress demo`, which runs
  the whole loop offline with no keys.
- Guards for MCP (`mcp-guard` proxy and executor), the OpenAI Agents SDK, Composio, and the Vercel AI SDK
  (npm [`benchpress-guard`](https://www.npmjs.com/package/benchpress-guard)), all sharing one policy format.
- Playbooks for Slack, Gmail, HubSpot, Stripe and GitHub.
- Four YAML policy packs (billing, customer success, IT offboarding, release engineering) enforced by the gate.
- A public gate-rule corpus (178 cases), `benchpress regress` to turn any run into permanent corpus cases,
  and `benchpress receipts export` for a local audit log of every write attempt.
- `benchpress rehearse` / `replay` on local stages: run a request N times, require convergence, replay the
  typed plan with no model.

Release notes: [CHANGELOG.md](CHANGELOG.md). Numbers and limits: [docs/RELIABILITY-BRIEF.md](docs/RELIABILITY-BRIEF.md).

## The problem it solves

Agents got write access to billing systems, CRMs and repos in 2026. Arga's published data shows the
best configuration still fails about 30% of realistic ops tasks, and 17% of all runs do something
unsafe. The failures come from the scaffold: agents don't read policy, can't tell look-alike
records apart, and report success from a 2xx. Every team shipping an agent with write access
rebuilds guardrails by hand, in prompts, and learns about the failures from customers.

## What this becomes

### Month 1: open core
- Playbooks beyond the five shipped providers, toward the 12 providers ArgaBench twins cover.
- Upstream the ArgaBench adapter as a community profile and publish a full 40-task row on hosted twins
  (needs multi-twin access).
- Grow the gate-rule corpus with outside contributions and cases generated by `benchpress regress`.
- **First 10 design partners:** teams whose agents already touch money and customers: RevOps, customer
  success (the renewal-rescue workflow) and platform teams.

### Month 3: Rehearse in production
- When a request arrives, fork the relevant **live** state into twins, run the plan N times, and require
  a converged final-state hash with zero refusals. Then replay the converged, typed plan against
  production with read-back on every write. (Rehearse and replay already run on local stages.)
- **The model never decides a production write live.** It decides in rehearsal, and code replays the result.
- Hosted receipts with audit export (SOC 2 evidence for "who changed this customer record and why").
  Audit export already runs locally.

### Month 6: closed loop
- Observability-fed regressions: every silent failure Lemma groups in production becomes a twin scenario
  and a permanent Benchpress regression case.
- More policy packs per function, authored in YAML and enforced by the gate.
- Target: 1,000 verified tasks/day across 30 teams. Unsafe rate 0 by construction on gated classes.

## Revenue model

- **Per verified task** for teams: $0.50–$2 per task that completes with full evidence. Refused and escalated tasks are free, which aligns our incentive with safety.
- **Platform tier** ($2k–$10k/mo) for rehearsal volume, hosted receipts, audit export and policy packs.
- Unit economics at 1,000 tasks/day × $1 is about $30k MRR on ~$4–6k of model spend.

## What is validated, and what is still a hypothesis

- **Validated, on one task:** on ArgaBench's ECOM-02 (0 of 111 published frontier runs pass), the same model
  goes from 0/3 in a stock loop to 3/3 with Benchpress on local twins graded by ArgaBench's unmodified
  grader, and turning off the policy sweep drops it back to 0/3. On real apps with the published seed both
  arms fail (Benchpress on one assertion, a HubSpot substrate limit); with the seed's hosts made routable,
  Benchpress passes 13 of 13 assertions. See [docs/RELIABILITY-BRIEF.md](docs/RELIABILITY-BRIEF.md).
- **Hypothesis:** the lift generalizes across the other 39 tasks. Teams will pay per verified task rather
  than build guardrails in-house. The rehearsal convergence gate works on live production state.
